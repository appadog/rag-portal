# Enterprise RAG Concept

## 1. 개요

Enterprise RAG는 조직이 보유한 업무 문서를 검색 가능한 지식으로 구성하고, 사용자의 질문과 관련된 지식을 찾아 근거와 출처가 포함된 답변을 제공하는 시스템이다.

시스템은 업무 문서의 지식화, 관련 지식의 검색, 근거 기반 답변, 품질 평가 및 운영 관찰을 일관된 범위 안에서 지원한다.

```text
업무 문서
  → 검색 가능한 지식
  → 관련 지식 검색
  → 근거 기반 답변
  → 품질 평가와 운영 관찰
  → 지속적 개선
```

Enterprise RAG는 모델, 검색 저장소, 프롬프트, 평가 도구 또는 모니터링 시스템 자체를 개발하고 운영하는 플랫폼이 아니다.

외부에서 결정되고 제공된 자원을 연계하여 RAG의 목적에 맞는 지식 처리와 질의응답을 수행한다.

---

## 2. 목적

Enterprise RAG의 목적은 다음과 같다.

- 조직의 업무 문서를 활용 가능한 지식으로 전환한다.
- 필요한 경우 최초 지식 생성 전에 처리·질의·검색 전략을 실제 결과로 비교하고 사용자가 선택할 수 있도록 한다.
- 사용자의 질문과 관련된 지식을 정확하게 검색한다.
- 확인된 지식 범위 안에서 신뢰할 수 있는 답변을 제공한다.
- 답변의 근거와 원본 출처를 확인할 수 있도록 한다.
- Tenant별 지식과 실행 범위를 분리한다.
- 검색과 답변 품질을 지속적으로 평가한다.
- 검색과 답변의 평가 결과와 품질 변화를 확인할 수 있도록 한다.
- 시스템의 처리 상태와 품질 상태를 외부에서 관찰할 수 있도록 한다.
- 외부 자원의 변경에 유연하게 대응한다.

---

## 3. 시스템 정의

> Enterprise RAG는 Tenant별 업무 문서를 검색 가능한 지식으로 구성하고, 필요한 경우 최초 지식 생성 전략의 후보 결과를 사용자가 비교·선택할 수 있도록 하며, 사용자의 질문과 관련된 지식을 찾아 해당 근거 범위 안에서 답변과 출처를 제공하고 검색 및 답변 품질과 실행 상태를 확인할 수 있도록 지원하는 지식 활용 시스템이다.

Enterprise RAG의 핵심 가치는 다음과 같다.

### 지식 활용

다양한 형태의 업무 문서를 조직이 검색하고 활용할 수 있는 지식으로 전환한다.

### 근거 기반 응답

검색된 지식에 근거하여 답변하고, 확인 가능한 근거가 없는 경우 이를 명확하게 알린다.

### 품질 개선

검색 결과와 답변을 평가하여 품질 상태를 파악하고 개선 방향을 도출한다.

### 운영 가시성

지식 처리와 질의응답 과정의 상태를 외부 운영 체계에서 관찰하고 분석할 수 있도록 한다.

---

## 4. 핵심 원칙

### 4.1 외부 결정, 내부 실행

Enterprise RAG가 사용하는 모델, 검색 저장소, 프롬프트, 평가 수단 및 모니터링 체계는 시스템 외부에서 결정하고 제공한다.

Enterprise RAG는 외부에서 결정된 자원을 이용하여 다음 절차를 수행한다.

- 업무 문서를 지식으로 구성한다.
- 사용자 질문과 관련된 지식을 검색한다.
- 검색된 근거를 바탕으로 답변을 생성한다.
- 검색 결과와 답변 품질을 평가한다.
- 실행 상태를 관찰할 수 있는 정보를 제공한다.

```text
외부 영역
- 모델 제공 및 운영
- 검색 저장소 제공 및 운영
- 프롬프트 작성 및 관리
- 평가 수단 제공
- 사용자 인증과 조직 관리
- 모니터링 정보의 수집·분석·시각화·알림

Enterprise RAG
- 외부 자원 관리 및 인터페이스
- 외부 자원 관리정보 유지
- 지식 구성
- 지식 검색
- 근거 기반 답변
- 품질 평가
- 관찰정보 제공
```

### 4.2 Tenant 중심 격리

Tenant는 Enterprise RAG에서 데이터와 실행 범위를 구분하는 최상위 경계이다.

모든 지식 처리, 검색, 대화, 평가 및 운영 정보는 Tenant 범위 안에서 관리되어야 한다.

Enterprise RAG는 Tenant 내부의 사용자별 Knowledge Base 권한을 구분하지 않는다. 동일 Tenant의 사용자는 해당 Tenant에 속한 Knowledge Base를 공통 범위로 사용한다.

대화 이력은 예외적으로 Tenant 경계와 함께 대화 소유 사용자를 기준으로 제한한다. 사용자는 동일 Tenant 안에서도 자신의 대화와 그 대화에 속한 질문, 답변 및 출처만 조회할 수 있다.

외부 자원 관리정보는 Tenant 소유 데이터가 아니라 Enterprise RAG 전체에서 공통으로 사용하는 시스템 구성정보로 관리한다. Tenant는 외부 자원 선택 기준이 아니라, 실행 결과와 사용된 구성의 관계를 추적하기 위한 실행 맥락으로만 기록한다.

Tenant 격리는 특정 기능에만 적용되는 선택적 기능이 아니라 시스템 전체에 공통으로 적용되는 기본 제약이다.

```text
Tenant
 ├─ 지식
 ├─ 문서
 ├─ 검색 범위
 ├─ 대화
 ├─ 실행 이력
 ├─ 사용자 피드백
 ├─ 평가 결과
 └─ 관찰정보
```

사용자 인증과 조직 관리는 외부 시스템이 담당하며, Enterprise RAG는 외부에서 검증된 Tenant 컨텍스트를 전달받아 사용한다.

사용자 식별정보는 대화 소유권 확인과 감사에 필요한 참조로만 사용하며, 일반적인 사용자별 권한 체계로 확장하지 않는다.

### 4.3 지식 범위 제한

Enterprise RAG의 답변은 제공된 지식 범위 안에서 생성되어야 한다.

검색된 근거가 질문에 답하기 충분한 경우에는 해당 근거를 이용하여 답변한다.

검색된 근거가 없거나 부족한 경우에는 외부 생성 모델이 보유한 일반 지식으로 내용을 추정하지 않고, 제공된 지식 범위에서는 답변을 확인할 수 없음을 안내한다.

```text
충분한 근거 존재
  → 근거 기반 답변 제공

근거 없음 또는 부족
  → 확인 가능한 정보가 없음을 안내
```

### 4.4 추적 가능한 결과

Enterprise RAG의 처리 결과는 그 근거와 실행 맥락을 확인할 수 있어야 한다.

다음 관계를 추적할 수 있어야 한다.

- 원본 문서와 구성된 지식의 관계
- 사용자 질문과 검색 결과의 관계
- 검색 결과와 생성된 답변의 관계
- 답변과 원본 출처의 관계
- 품질 평가와 평가 대상 결과의 관계
- 품질 변경과 평가 결과의 관계

추적 가능성은 답변 신뢰성 확인, 문제 분석, 품질 평가 및 감사의 기반이 된다.

### 4.5 교체 가능한 외부 연계

Enterprise RAG는 특정 모델, 저장소, 프롬프트 관리 방식, 평가 도구 또는 모니터링 제품에 종속되지 않아야 한다.

동일한 목적과 역할을 수행하는 외부 자원은 시스템의 핵심 책임을 변경하지 않고 교체할 수 있어야 한다.

교체 가능한 외부 자원의 범위는 다음과 같다.

- 문서 해석 자원
- 임베딩 생성 자원
- 답변 생성 자원
- 지식 검색 저장소
- 프롬프트 자원
- 품질 평가 자원
- 모니터링 및 관찰정보 활용 시스템

### 4.6 측정 가능한 품질

검색과 답변의 품질은 주관적인 판단에만 의존하지 않아야 한다.

Enterprise RAG는 품질을 반복적으로 확인할 수 있는 평가 기준과 결과를 확보해야 한다.

품질 평가는 다음 질문에 답할 수 있어야 한다.

- 질문에 필요한 지식이 검색되었는가?
- 검색된 지식은 질문과 관련성이 있는가?
- 검색 결과가 답변을 생성하기에 충분한가?
- 답변이 검색된 근거에 충실한가?
- 답변이 사용자의 질문에 적절한가?
- 답변의 출처가 내용과 일치하는가?
- 평가 결과가 이전과 비교해 어떻게 변화했는가?

구체적인 평가 지표와 산정 방식은 후속 설계 단계에서 정의한다.

### 4.7 평가와 운영 변경의 분리

평가 결과는 품질 개선을 위한 판단 근거로 사용한다.

평가 결과가 시스템의 검색 방식이나 운영 조건을 자동으로 변경하는 것은 기본 범위에 포함하지 않는다.

```text
평가
  → 개선 필요 영역 식별
  → 변경안 검토
  → 변경 적용
  → 재평가
```

평가와 변경 적용을 분리하여 품질 변경의 통제 가능성과 추적 가능성을 확보한다.

### 4.8 외부 관찰 중심 모니터링

Enterprise RAG는 모니터링 정보를 자체적으로 수집·저장·분석·시각화하는 별도의 모니터링 시스템을 내부에 구축하지 않는다.

시스템은 OpenTelemetry 기반의 표준화된 관찰정보를 제공하고, 외부 모니터링 시스템이 이를 수집하고 활용할 수 있도록 한다.

Enterprise RAG가 제공하는 관찰정보는 다음 관점을 지원해야 한다.

- 지식 처리 과정의 상태
- 사용자 질의 처리 흐름
- 외부 자원 호출 상태
- 처리 성능과 지연
- 오류와 실패
- Tenant별 실행 범위
- 검색 및 답변 품질 상태
- 품질 평가 실행 상태

외부 모니터링 시스템은 다음 책임을 가진다.

- 관찰정보 수집
- 관찰정보 보존
- 조회 및 분석
- 대시보드와 시각화
- 이상 상태 탐지
- 경보와 알림
- 장기 추세 분석

```text
Enterprise RAG 실행
  → OpenTelemetry 기반 관찰정보 제공
  → 외부 모니터링 시스템 수집
  → 분석·시각화·경보
```

OpenTelemetry 적용 범위, 전달 방식 및 외부 시스템 연계 구조는 후속 아키텍처와 상세 설계 단계에서 정의한다.

## 5. 시스템 범위

Enterprise RAG의 책임 범위는 다음 Capability로 구분한다.

```text
Enterprise RAG

1. 지식 관리
2. 지식 검색
3. 대화 및 답변
4. 외부 자원 관리 및 인터페이스
5. 품질 관리
6. 운영 및 관찰
```

이 Capability는 시스템이 수행해야 하는 논리적 책임 영역을 의미한다.

특정 구성요소, 서비스, 프로세스 또는 배포 단위를 의미하지 않으며, 구체적인 구조는 로지컬 아키텍처 단계에서 정의한다.

### 5.1 지식 관리

지식 관리는 사용자가 제공한 업무 문서를 검색하고 활용할 수 있는 지식으로 구성하고 유지하는 영역이다.

주요 책임은 다음과 같다.

- 업무 문서 수용
- 초기 지식 생성 전에 후보 처리·질의·검색 전략의 결과 비교
- 사용자의 명시적인 지식 생성 전략 선택
- 원본 문서와 변경 상태 관리
- 문서의 내용과 구조 해석
- 검색 가능한 지식 구성
- 검색을 위한 지식 표현 생성
- 지식의 검색 가능 상태 관리
- 문서 변경에 따른 지식 갱신
- 문서와 지식의 관계 유지

지식 관리는 문서의 원본 형식과 관계없이 일관된 검색 대상으로 전환하는 것을 목적으로 한다.

#### 선택적 기능: 지식 생성 전략 선택

지식 생성 전략 선택은 최초 지식 생성 전에 업로드된 문서의 대표 범위를 이용하여 후보 처리·질의·검색 전략의 결과를 비교하고, 사용자가 전체 지식 생성에 적용할 전략을 선택하도록 지원하는 기능이다.

후보별 임시 비교 결과는 동일한 질문에 대한 답변, 출처와 원본 근거를 제공한다. 사용자는 실제 결과를 비교하여 하나의 전략을 명시적으로 확정하며, 최종 지식은 확정된 전략으로 전체 문서를 처리하여 새로 구성한다.

다음 원칙을 적용한다.

- 선택 기능을 사용하지 않으면 사전에 지정된 기본 전략으로 지식을 구성한다.
- 후보 비교 결과는 운영 검색에 노출되는 지식이 아니다.
- 후보별 임시 지식과 검색 범위는 서로 혼합하지 않는다.
- 사용자가 선택하는 대상은 임시 지식이 아니라 지식 생성에 적용할 전략이다.
- 사용자 선택과 최종 확정 없이 운영 지식을 게시하지 않는다.
- 선택되지 않은 후보의 임시 결과는 비교 종료 후 정리한다.
- 사용자 후보 선택은 운영 답변에 대한 품질 피드백과 구분한다.
- 게시 이후 전략 변경과 기존 지식 재구성은 초기 선택 기능의 범위에 포함하지 않는다.

초기 비교 대상은 청킹, 질의 처리, 검색과 결과 구성 방법으로 제한한다. 외부 자원 구성정보는 시스템 공통으로 관리하며 하나의 선택 과정에는 동일하게 적용한다. 임베딩 모델과 같은 외부 자원을 후보로 비교하는 기능은 별도 정책 변경이 필요한 확장 범위로 둔다.

### 5.2 지식 검색

지식 검색은 사용자의 질문과 관련된 지식을 지정된 Tenant와 지식 범위 안에서 찾는 영역이다.

주요 책임은 다음과 같다.

- 사용자의 질문과 검색 의도 해석
- 검색 범위 확인
- 관련 지식 탐색
- 검색 결과의 관련성 판단
- 불필요하거나 중복된 결과 정리
- 답변에 사용할 근거 구성
- 검색 결과의 충분성 판단

검색 방법은 특정 기술이나 알고리즘에 한정하지 않는다.

구체적인 검색 방식과 처리 전략은 후속 설계 단계에서 결정한다.

### 5.3 대화 및 답변

대화 및 답변은 사용자의 질문, 대화 맥락 및 검색된 지식을 결합하여 근거 기반의 응답을 제공하는 영역이다.

주요 책임은 다음과 같다.

- 대화 맥락 유지
- 검색된 지식과 사용자 질문의 결합
- 외부 프롬프트 적용
- 외부 생성 자원을 통한 답변 생성
- 지식 범위를 벗어나는 답변 제한
- 답변과 출처 연결
- 질의응답 결과 유지

대화 이력은 검색된 지식을 보완하는 맥락으로 활용할 수 있으나, 검증된 지식 근거를 대체하지 않는다.

### 5.4 외부 자원 관리 및 인터페이스

외부 자원 관리 및 인터페이스는 Enterprise RAG가 자체적으로 제공하거나 운영하지 않는 자원에 대한 공통 관리정보를 유지하고, 실행 영역이 지정된 자원과 상호작용할 수 있도록 하는 영역이다.

외부 자원의 관리 책임과 실행 시 상호작용 책임은 다음과 같이 구분한다.

#### 외부 자원 관리

외부에서 결정된 모델, 검색 저장소, 프롬프트 및 평가 수단의 참조정보와 적용 관계를 시스템 공통으로 관리한다. 외부 임베딩 자원과 외부 자원 구성정보도 Tenant와 관계없는 시스템 공통 정보로 관리한다.

- 외부 자원 프로파일과 역할 관리
- 자원 간 호환성 정보 관리
- 실행에 적용할 공통 구성과 적용 관계의 추적
- 구성의 활성화, 비활성화 및 이전 구성으로의 복원 지원
- 실행 결과와 사용된 구성의 관계 유지

외부 자원 관리정보는 Tenant별로 분리하거나 Tenant별 자원 선택에 사용하지 않는다. 모든 Tenant는 시스템 공통 구성 집합을 참조하며, 구성 전환 기간에는 이전 구성과 새 구성이 공통 구성 이력 안에서 함께 유효할 수 있다. 실제 인증정보와 Secret 값은 외부 Secret 관리 체계의 책임이며 Enterprise RAG는 참조정보만 관리한다.

##### 외부 자원 구성 이력 범위

외부 자원 구성 이력은 지식 게시와 실행 결과의 호환성, 추적성 및 복원을 지원하는 범위로 제한한다.

이력 관리 대상은 다음과 같다.

- 외부 자원의 역할 및 식별 참조 변경
- 임베딩 모델, 검색 저장소, 생성 모델, 프롬프트 및 평가 수단의 적용 구성 변경
- 지식 구성과 검색 결과에 영향을 주는 호환성 정보 변경
- 외부 자원 구성의 적용, 적용 종료 및 복원 관계
- 지식 게시, 검색, 답변 및 평가 결과에 실제 적용된 외부 자원 구성정보

다음 정보는 외부 자원 구성 이력의 대상에 포함하지 않는다.

- Secret, Token 및 인증정보 원문과 그 교체 이력
- 외부 자원의 일시적인 가용성, 지연 및 오류 상태
- 실행 결과와 호환성에 영향을 주지 않는 설명 또는 표시정보 변경

외부 자원의 일시적인 상태는 운영 관찰정보로 다루고, Secret 변경 이력은 외부 Secret 관리 체계가 책임진다. 외부 자원 구성정보와 외부 자원의 현재 상태가 다르다는 이유만으로 구성을 자동 비활성화하지 않으며, 적용 상태 변경은 명시적인 관리 결정에 따른다.

구성 변경의 저장 단위, 변경 전후 관계, 보존 기간 및 세부 상태는 후속 상세 설계와 데이터 설계에서 정의한다.

#### 외부 자원 인터페이스

지식 구성, 검색, 답변 및 평가 영역이 적용된 외부 자원 구성정보를 확인하고, 해당 구성정보가 참조하는 외부 자원과 상호작용할 수 있도록 논리적 접점을 제공한다.

연계 대상은 다음과 같다.

#### 문서 해석 자원

업무 문서의 내용과 구조를 이해하는 데 사용한다.

#### 임베딩 자원

문서와 질문을 검색 가능한 표현으로 변환하는 데 사용한다.

#### 생성 자원

검색된 근거를 바탕으로 사용자 답변을 생성하는 데 사용한다.

#### 지식 검색 저장소

지식 표현을 보관하고 관련 지식을 검색하는 데 사용한다.

#### 프롬프트 자원

답변의 목적, 형식 및 제약을 정의하는 데 사용한다.

#### 평가 자원

검색 결과와 답변 품질을 측정하는 데 사용한다.

Enterprise RAG는 외부 자원의 개발, 학습, 배포, 제품 선택 및 인프라 운영을 담당하지 않는다.

외부 자원 관리와 인터페이스는 외부 자원을 자동 선택하거나 실행 요청을 임의로 다른 자원에 라우팅하지 않는다.

### 5.4.1 지식 게시와 임베딩 호환성

검색 가능한 지식은 지식이 게시될 때 사용된 임베딩 구성과 현재 검색 실행 구성이 호환되는 경우에만 사용한다.

하나의 검색 범위에는 동일한 임베딩 구성정보와 호환되는 지식 게시 단위만 포함할 수 있다. 서로 호환되지 않는 임베딩 구성이 적용된 지식 게시 단위를 하나의 검색 범위에 혼합하지 않는다.

임베딩 구성이 변경되면 기존 지식을 개별 단위로 직접 수정하지 않고, 동일한 구성 기준으로 생성된 지식 게시 단위를 새로 준비하여 검증한다.

새 게시 단위가 사용 가능한 상태가 되기 전까지 기존 게시 단위를 유지하고, 준비가 완료된 후 활성 게시 단위를 전환한다. 문제가 발생하면 이전 게시 단위로 복원할 수 있어야 한다.

```text
공통 외부 자원 구성 변경
  → Tenant·Knowledge Base별 지식 재구성 및 재게시
  → 새 게시 단위의 호환성 확인
  → 활성 게시 단위 전환
  → 필요 시 이전 게시 단위로 복원
```

외부 자원 관리 영역은 시스템 공통 임베딩 자원, 외부 자원 구성정보와 호환성 기준을 관리하고, 지식 관리 영역은 Tenant와 Knowledge Base별 지식 재구성, 게시 및 활성 상태를 책임진다. 지식 검색 영역은 하나의 검색 실행에 적용된 외부 자원 구성정보와 호환되며 활성화된 게시 단위만 사용한다.

### 5.5 품질 관리

품질 관리는 검색 결과와 생성 답변의 품질을 평가하고 개선하기 위한 근거를 제공하는 영역이다.

Quality Evaluation의 핵심 범위는 운영 또는 평가 실행에서 생성된 검색 결과와 응답을 평가하는 것이다. 서로 다른 외부 자원 구성의 비교 평가는 선택적 확장 범위로 둔다.

품질 관리는 다음 책임을 포함한다.

#### 사용자 피드백

사용자가 검색 결과 또는 답변에 대해 제공한 평가와 의견을 수집한다.

사용자 피드백은 다음 내용을 파악하는 데 활용할 수 있다.

- 답변의 유용성
- 답변의 정확성
- 검색 결과의 적절성
- 출처의 적절성
- 누락되거나 잘못된 내용

피드백은 품질 문제를 식별하는 근거이며, 그 자체가 시스템 설정을 자동으로 변경하지 않는다.

#### 검색 품질 평가

질문에 필요한 지식이 적절하게 검색되었는지를 평가한다.

주요 평가 관점은 다음과 같다.

- 필요한 지식이 검색되었는가?
- 필요한 지식이 적절한 우선순위로 제시되었는가?
- 불필요한 정보가 과도하게 포함되지 않았는가?
- 검색 결과가 답변에 충분한 근거를 제공하는가?

#### 답변 품질 평가

생성된 답변이 질문과 검색 근거에 적합한지를 평가한다.

주요 평가 관점은 다음과 같다.

- 답변이 질문에 부합하는가?
- 답변이 검색된 근거에 충실한가?
- 근거에 없는 내용이 포함되지 않았는가?
- 필요한 내용을 충분히 전달하는가?
- 답변과 출처가 일치하는가?

#### 평가 기준

동일한 조건으로 품질을 반복적으로 측정하기 위한 기준을 관리한다.

평가 기준은 대표 질문, 기대 결과, 관련 지식 및 평가 관점 등을 포함할 수 있다.

구체적인 구성과 관리 방식은 후속 설계에서 정의한다.

#### 외부 평가 수단 활용

Enterprise RAG는 특정 평가 도구나 프레임워크에 종속되지 않는다.

RAGAS와 같은 평가 도구는 검색과 답변 품질을 측정하기 위한 외부 평가 수단 중 하나로 활용할 수 있다.

```text
평가 대상 결과
  → 외부 평가 수단 적용
  → 평가 결과 수집
  → 품질 분석
```

#### 선택적 확장: 자원 구성 비교 평가

서로 다른 외부 자원 구성을 동일한 평가 기준으로 비교하는 기능은 선택적으로 확장할 수 있다.

확장하는 경우에도 시스템 공통으로 관리되는 외부 자원 구성정보를 평가 실행에 명시적으로 적용하며, Tenant별 자원 할당이나 운영 구성의 자동 변경으로 사용하지 않는다.

### 5.6 운영 및 관찰

운영 및 관찰은 지식 처리, 검색, 답변 및 평가 과정이 안정적으로 수행되는지를 확인하고 외부 운영 체계가 이를 관찰할 수 있도록 하는 영역이다.

주요 책임은 다음과 같다.

- 업무 처리 상태 확인
- 실패와 중단 상태 식별
- 재처리가 필요한 대상 식별
- 외부 자원 인터페이스 상태 확인
- 실행 이력 유지
- 품질 상태 관찰
- 문제 분석을 위한 정보 제공
- OpenTelemetry 기반 관찰정보 제공
- 외부 모니터링 시스템과의 연계 지원

Enterprise RAG는 모니터링 데이터를 장기 저장하거나 자체 대시보드와 경보 체계를 제공하는 것을 기본 책임으로 하지 않는다.

관찰정보의 저장, 분석, 시각화 및 알림은 외부 모니터링 시스템의 책임이다.

## 6. 핵심 개념

### Tenant

지식, 검색, 대화, 평가 및 운영 정보가 분리되는 최상위 범위이다.

### Knowledge Base

특정 업무 목적이나 주제에 따라 구성된 지식의 집합이다.

### Document

지식의 원천이 되는 업무 자료이다.

### Document Version

문서의 변경 상태와 지식 구성 시점을 구분하기 위한 개념이다.

### Knowledge Unit

문서에서 추출되어 검색과 답변에 활용되는 지식의 단위이다.

구체적인 구성 기준과 형태는 후속 설계에서 정의한다.

### Knowledge Representation

지식 단위를 검색 가능한 형태로 표현한 결과이다.

특정 기술이나 데이터 형식으로 한정하지 않는다.

### Conversation

사용자와 시스템 간에 이어지는 질의응답의 맥락이다.

Conversation은 Tenant에 속하며, 외부에서 전달된 사용자 식별정보를 소유자 참조로 가진다. 대화와 그 하위 정보는 해당 소유자만 접근할 수 있다.

### Retrieval Result

사용자 질문과 관련된 것으로 판단된 지식의 집합이다.

### Citation

답변과 원본 지식의 관계를 나타내는 출처정보이다.

### Feedback

사용자가 검색 결과 또는 답변에 대해 제공한 평가정보이다.

### Candidate Strategy

최초 지식 생성 전에 비교할 문서 처리, 청킹, 질의 처리 및 검색 방법의 조합이다.

### Strategy Selection

후보 전략의 실제 검색·답변 결과를 비교하고 전체 지식 생성에 적용할 전략을 사용자가 명시적으로 확정하는 과정이다.

### Selected Knowledge Generation Strategy

사용자가 확정하여 Knowledge Base의 초기 전체 지식 생성에 적용되는 전략이다. 적용된 시스템 공통 외부 자원 구성정보와 구분하여 추적한다.

### Temporary Comparison Result

후보 전략을 비교하기 위해 문서의 대표 범위로 생성한 임시 지식, 검색 결과, 답변과 출처의 집합이다. 운영 지식으로 게시하지 않으며 선택 과정이 종료되면 정리한다.

### Evaluation Criteria

검색과 답변 품질을 반복적으로 판단하기 위한 기준이다.

### Evaluation Result

특정 조건에서 수행된 검색과 답변에 대한 평가 결과이다.

### External Resource Reference

외부에서 결정된 모델, 검색 저장소, 프롬프트, 평가 수단 또는 모니터링 시스템을 사용하기 위한 참조 개념이다.

### Resource Profile

외부에서 결정된 자원의 역할, 연결 참조 및 호환성 정보를 표현하는 시스템 공통 관리 개념이다.

### 외부 자원 구성정보

지식 구성, 검색, 답변 및 평가에 사용할 역할별 외부 자원의 참조, 적용 관계와 호환성 기준을 표현하는 시스템 공통 관리 개념이다. 실제 인증정보 원문을 포함하지 않으며, 실행 또는 지식 게시 결과와 실제 적용된 구성의 관계를 추적할 수 있어야 한다.

### Knowledge Publication

동일한 지식 구성과 외부 자원 구성 기준으로 생성되어 함께 활성화하거나 비활성화할 수 있는 검색 가능 지식의 게시 단위이다.

### Observability Information

시스템의 실행 흐름, 상태, 성능 및 오류를 외부에서 관찰할 수 있도록 제공되는 정보이다.

## 7. 논리적 처리 흐름

### 7.1 지식 구성

```text
업무 문서 제공
  → 필요 시 후보 전략 결과 비교
  → 사용자 지식 생성 전략 선택
  → 문서 내용 해석
  → 검색 가능한 지식 구성
  → 지식 표현 생성
  → 검색 가능 상태로 반영
```

지식 생성 전략 선택을 사용하는 경우의 흐름은 다음과 같다.

```text
업무 문서 제공
  → 대표 범위 선정
  → 후보 전략별 임시 비교 결과 준비
  → 동일 질문에 대한 후보별 검색·답변 결과 제공
  → 사용자 비교·선택 및 최종 확정
  → 선택된 전략으로 전체 문서 처리
  → 최종 지식 게시
  → 임시 비교 결과 정리
```

### 7.2 지식 검색 및 답변

```text
사용자 질문
  → 검색 범위 확인
  → 관련 지식 검색
  → 검색 결과 적합성 판단
  → 검색된 지식 기반 답변 생성
  → 답변과 출처 제공
```

### 7.3 피드백 및 품질 평가

```text
검색 결과와 답변
  → 사용자 또는 평가 기준에 의한 평가
  → 품질 결과 축적
  → 품질 문제와 개선 대상 식별
  → 변경 후 재평가
```

### 7.4 운영 및 모니터링

```text
지식 처리·검색·답변·평가 실행
  → OpenTelemetry 기반 관찰정보 생성
  → 외부 모니터링 시스템 전달
  → 상태 분석·시각화·이상 탐지·알림
```

이 흐름은 시스템 책임 간의 관계를 나타낸다.

구체적인 처리 순서, 구성요소, 호출 관계, 통신 방식 및 저장 방식은 본 문서에 정의하지 않는다.

## 8. 시스템 경계

### 8.1 Enterprise RAG가 책임지는 범위

- 업무 문서를 지식으로 전환하는 과정
- 지식의 검색 가능 상태 관리
- Tenant 범위 내 관련 지식 검색
- 검색 결과를 활용한 근거 기반 답변
- 답변과 원본 출처의 연결
- 대화 맥락 관리
- 사용자 피드백 수집
- 초기 지식 생성 전략의 비교·선택과 선택 결과 추적
- 검색 및 답변 품질 평가
- 검색 및 답변 평가 결과와 품질 변화 확인
- 지식 처리와 질의응답 실행 이력 관리
- 외부 자원의 공통 관리정보와 구성 이력 관리
- 외부 자원의 인터페이스 사용
- 지식 게시 단위의 활성화, 비활성화 및 복원
- OpenTelemetry 기반 관찰정보 제공
- 외부 모니터링 연계 지원

### 8.2 Enterprise RAG가 책임지지 않는 범위

- 사용자 인증
- 조직 및 사용자 관리
- Tenant 내부 사용자별 Knowledge Base 권한 관리
- 모델 개발과 학습
- 모델 배포와 운영
- 모델 자동 선택과 라우팅
- 검색 저장소 설치와 인프라 운영
- 프롬프트 작성과 생명주기 관리
- 평가 도구 자체의 개발과 운영
- 모니터링 정보의 장기 저장
- 모니터링 대시보드 제공
- 이상 탐지 및 경보 정책 관리
- 평가 결과에 따른 운영 조건 자동 변경
- 외부 지식의 자동 수집
- 검색 근거가 없는 일반 지식 기반 답변
- 범용 인공지능 비서 기능
- 자율적인 업무 수행

## 9. 기대 효과

Enterprise RAG를 통해 다음 효과를 기대할 수 있다.

- 분산된 업무 문서를 조직의 지식으로 활용할 수 있다.
- 사용자는 필요한 정보를 대화 방식으로 탐색할 수 있다.
- 답변의 근거와 출처를 확인할 수 있다.
- Tenant별 지식 경계를 유지할 수 있다.
- 특정 외부 모델이나 저장소에 대한 종속성을 줄일 수 있다.
- 검색과 답변 품질을 지속적으로 확인할 수 있다.
- 품질 저하 원인을 식별하고 평가 결과의 변화를 확인할 수 있다.
- 외부 모니터링 체계에서 시스템 실행 상태를 통합 관찰할 수 있다.
- 시스템 내부에 별도 모니터링 플랫폼을 구축하지 않고 기존 운영 체계와 연계할 수 있다.

---

## 10. 최종 정의

> Enterprise RAG는 Tenant별 업무 문서를 검색 가능한 지식으로 구성하고, 사용자의 질문과 관련된 지식을 찾아 해당 근거 범위 안에서 답변과 출처를 제공하는 시스템이다. 또한 사용자 피드백과 품질 평가를 통해 검색 및 답변의 신뢰성을 지속적으로 확인하고, OpenTelemetry 기반 관찰정보를 외부 모니터링 시스템에 제공하여 처리 상태와 품질 상태를 운영 체계에서 관찰할 수 있도록 지원한다.

```text
Tenant 기반 지식 격리
        +
업무 문서의 지식화
        +
관련 지식 검색
        +
근거와 출처가 포함된 답변
        +
검색 및 답변 품질 평가
        +
OpenTelemetry 기반 외부 관찰
        +
평가와 관찰에 기반한 지속적 개선
```
