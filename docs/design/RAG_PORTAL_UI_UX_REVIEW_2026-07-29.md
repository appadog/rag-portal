# RAG Portal UI/UX 리뷰

> 리뷰 일자: 2026-07-29 · 범위: RAG 상세 검색 화면 · 기준: `ui_ux_reviewer_long.md`, NotebookLM-inspired UI 원칙, `RAG_PORTAL_FEATURE_PLAN.md`

## 요약

- 종합: **8.4 / 10** — 문서 범위, 검색, 근거 확인의 정보 구조가 명확하고, 검색의 진행·중단·연결 실패 상태까지 실제 API 계약으로 연결했다.
- 릴리스 의견: **현재 MVP 범위 승인**. 실제 장기 실행 워커를 도입할 때에는 job 취소·재시도 API를 추가 검증한다.
- 검증 폭: 1440×900, 1280×720, 390×844. 키보드 기반 인용 열기/닫기와 검색 중단 회귀 테스트를 포함했다.

## 이번에 해결한 항목

| 우선순위 | 이슈와 원인 | 사용자 영향 | 변경 및 완료 기준 |
| --- | --- | --- | --- |
| P0 | 브라우저, LNB, 본문이 같은 문서 스크롤에 의존해 긴 문서/대화에서 위치를 잃기 쉬웠다. | 문서 목록을 보다가 대화 위치가 함께 움직여 탐색 맥락이 무너진다. | 앱 셸은 화면 높이를 소유하고, LNB와 상세 패널은 각각 독립 `overflow-y: auto`로 분리했다. 본문은 1380px 이하에서만 세로 흐름을 소유한다. |
| P0 | 1280px에서 3개 패널의 최소 폭과 본문 패딩 합계가 가용 폭을 넘었고, 우측 Output이 잘렸다. | 근거·설정이 보이지 않아 핵심 검증 행동을 할 수 없다. | 1380px 이하에서 Output을 다음 행으로 배치했다. 1280px에서 가로 잘림 없이 전체 폭으로 표시되는 것을 확인했다. |
| P1 | 채팅 메시지, 민감도 선택, 질문 입력이 경계선과 서로 너무 가까워 보일 수 있었다. | 질문을 입력하는 영역과 이전 대화의 경계가 모호하다. | 대화 영역에 독립 스크롤·내부 패딩을 적용하고, composer에 분리선·상단 여백·일관된 12px 간격을 적용했다. |
| P1 | 인용 상세는 화면 내 보조 패널인데 modal dialog로 선언되어 있었다. | 보조 패널과 실제 모달의 키보드 동작이 불일치할 수 있다. | `aside`의 보조 영역 의미를 유지하고, 인용 열기 시 제목으로 포커스 이동·Escape 닫기·인용 칩으로 포커스 복귀를 유지했다. |
| P2 | 모바일에서 제목 옆의 도구 버튼이 세로로 좁게 쌓였다. | 제목을 읽는 흐름이 끊기고 터치 대상의 관계가 약해진다. | 720px 이하에서 도구 버튼을 제목·설명 아래의 한 줄 영역으로 이동했다. |
| P1 | 실제 답변 스트리밍/중단 상태가 UI 계약으로 완결됐는지 확인되지 않았다. | 연결이 느리거나 끊기면 사용자가 기다리는 이유와 이미 받은 내용을 잃을 수 있다. | 백엔드 SSE(`citations`/`token`/`done`)를 연결했다. 중단·연결 실패 시 부분 답변과 근거를 보존하고, 완료 답변으로만 확정한다. |
| P1 | 문서 준비·재튜닝의 최신 상태가 상세 화면에 드러나지 않았다. | 화면을 떠났다가 돌아오면 최근 준비 작업과 다음 행동을 파악하기 어렵다. | 서버의 `latest_job`을 표시하고, 종료되지 않은 job만 2초 간격으로 다시 읽는다. 현재 백엔드는 완료 상태를 즉시 반환하므로 가짜 진행률은 표시하지 않는다. |
| P2 | 검색 민감도의 차이를 선택 전에는 알기 어려웠다. | 비전문가가 용어만 보고 결과 범위를 예측하기 어렵다. | 선택된 값에 따라 쉬운 말의 한 줄 설명을 즉시 제공하고 group의 접근 가능한 설명으로 연결했다. |
